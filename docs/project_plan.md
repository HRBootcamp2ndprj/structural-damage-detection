# 프로젝트 계획서 — Z24 교량 손상 탐지 (시뮬 학습, 실측 검증)

- 발표: 2026-11-20(금)
- 인원: 4명 (A, B, C, D)
- 작업 기간: 11/16(월) ~ 11/19(목)

## 1. 목표

OpenSees로 Z24 교량을 모델링해 손상별 고유진동수를 만들고, 그것만으로 학습한 모델이 실측 Z24 데이터에서 손상을 찾아내는지 검증한다.

**성공 기준**
- 손상 유무: 실측 테스트 균형 정확도가 이상탐지 하한보다 높다.
- 손상 그룹: 최소한 침하(40mm 이상)는 실측에서 침하로 분류된다.

## 2. 범위

| 포함 | 제외 |
|---|---|
| 손상 유무 판별 (메인) | 17개 시나리오 개별 분류 |
| 4그룹 분류 + 3그룹 기준 보고 | 시뮬 시계열 합성 (시간 남으면 검증용) |
| 침하 크기 순위 (확장) | 모드형상·전달률 특징 (센서 위치 미상) |
| Flask 대시보드 | DB, 모델 추론 API |
| | 실측 손상 데이터로 미세조정·도메인 적응 |

## 3. 결정 기록

| # | 질문 | 결정 | 근거 문서 |
|---|---|---|---|

| Q3 | FE 모델 수준 | 3D spine 보 모델 (`elasticBeamColumn` + 교각·지점 스프링), 14+30+14m | `configs/fem.yaml` |
| Q4 | 실측 사용 범위 | 시나리오 0은 보정·f₀·σ₀ 전용, 나머지는 테스트 | ADR 0002 |
| Q5 | 라벨 정리 | 0·7 손상없음 / 1 제외 / 2~6 침하 / 8~11 국부손상 / 12~16 프리스트레스 손실. 10·11은 미시뮬 손상 | `src/data/labels.py`, CONTEXT.md |
| Q6·Q8 | 역할 | §4 참고. 실측 FDD는 A | 이 문서 §4 |

| Q10 | 국부손상 처리 | 4그룹으로 학습, 3그룹(경미 손상 합침) 기준도 함께 보고 | evaluation_protocol.md |
| S1 | 실측 기준선 | 시나리오 0의 setup별 진동수 **중앙값**. 산포 σ₀는 시뮬 노이즈 기준 | ADR 0001, 0002 |
| S2 | 대시보드 | Flask + HTML/JS, 파일만 읽음 | ADR 0003, app/README.md |
| S3 | 누수 방지 | 손상 모델링·튜닝에 실측 손상 데이터 사용 금지 | ADR 0002 |
| S4 | 손상 강도 | 시뮬은 연속 severity로 샘플링, mm에 맞추지 않음 | ADR 0004 |

## 4. 역할

| 담당 | 범위 | 산출물 |
|---|---|---|
| **A** 데이터 생성/정형 | 실측 다운로드·전처리(detrend, 글리치 제거)·FDD, 시뮬 데이터 생성, 특징 CSV | `real_features.csv`, `sim_features.csv`, f₀·σ₀ |
| **B** 모델 | 손상 유무·그룹 분류기, 침하 회귀(확장), 비교 실험 | `outputs/<실험>/metrics.json`, `predictions.csv` |
| **C** 시뮬레이터 | OpenSees 3D spine 모델, 보정, 그룹별 손상 함수, 모드 대응 | `src/fem/api.py: run_modal()` |
| **D** 대시보드 | Flask 대시보드(프론트/백엔드), 평가 시각화, 발표 자료 | `app/`, 발표 자료 |

인터페이스 세부 내용은 [interfaces.md](interfaces.md)에 있다.

## 6. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| A의 실측 FDD 지연 | C 보정, B·D 실데이터 연결이 모두 밀림 | 화요일까지 완료. 늦어지면 D가 지원. C는 문헌값으로 먼저 진행 |
| `run_modal` 인터페이스 변경 | A의 생성 코드 재작업 | 월요일에 확정, 이후 변경은 A와 C가 합의 |
| FE 보정이 안 맞음 (특히 횡·비틀림 모드) | 시뮬 진동수 대응 실패 | Δf/f₀로 절대 오차 상쇄. 안 맞는 모드는 특징에서 제외하고 그 사실을 보고 |
| FDD로 9.8/10.3Hz 모드가 섞임 | 고차 모드 특징의 신뢰도 저하 | setup 단위 600초 신호 + 봉우리 보간. 필요하면 해당 모드 제외 |
| 경미 손상 탐지 실패 | 그룹 분류 성능 저하 | 예상된 한계로 보고(3그룹 비교, ADR 0001) |
| 실측 결과를 보고 튜닝하고 싶은 유혹 | 누수, 결과 신뢰성 상실 | ADR 0002 규칙. 튜닝은 시뮬 검증 분할로만 |

## 7. 발표 구성 (안)

1. 문제: 실측 손상 데이터 없이 손상을 탐지할 수 있는가
2. Z24 교량과 데이터 (센서 위치 문제, HF README 오류)
3. 접근: 시뮬레이터 → Δf/f₀ → 분류기
   - 가정을 명시한다: "시뮬 + 실측 손상 전 기준값 1세트"
4. 시뮬레이터: FE 모델, 보정 결과, 손상 함수
5. 결과: 손상 유무, 4그룹 / 3그룹, 침하 순위, 미시뮬 손상 10·11
6. 비교 실험: 절대값 vs Δf/f₀, 600초 vs 60초, 상한·하한
7. 한계와 다음 단계 (센서 위치 확보, 시계열 합성, 도메인 적응)
8. 대시보드 시연
